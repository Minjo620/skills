# 可组合的叙事模式

## 选择原则

文章结构由「读者要理解什么」「系统怎样运行」「源码证据集中在哪里」共同决定。仓库类型只能提供线索，不能直接决定模板。

选择 1 条主线，再选不超过 2 种辅助模式。主线决定章节顺序，辅助模式只在局部降低理解难度。

## 主线模式

| 模式 | 适用问题 | 常见顺序 |
| --- | --- | --- |
| 架构全景 | 多个组件怎样分工和协作 | 问题 → 全景 → 组件 → 协作 → 边界 |
| 生命周期 | 一个对象从产生到销毁经历什么 | 触发 → 状态变化 → 持久化 → 读取 → 清理 |
| 端到端路径 | 一次请求或任务怎样穿过系统 | 输入 → 调用链 → 状态 → 输出 → 异常 |
| 状态机 | 行为由状态和转换决定 | 状态 → 事件 → 转换 → 不变量 → 恢复 |
| 问题与机制 | 系统在多个约束下如何取舍 | 问题 → 约束 → 机制 → 代价 → 替代方案 |
| 设计演化 | 当前结构由兼容性和历史形成 | 旧问题 → 变化 → 当前方案 → 遗留约束 |
| 范式对比 | 两种实现的共同点和差异是什么 | 比较维度 → 对应机制 → 差异原因 → 适用边界 |

## 仓库线索

| 仓库特征 | 优先考虑 |
| --- | --- |
| 应用产品 | 用户行为、业务流程、状态变化 |
| 基础设施或运行时 | 生命周期、并发、故障恢复、资源边界 |
| 框架或库 | 核心抽象、端到端调用、扩展机制 |
| 编译器或数据库 | 处理管线、状态机、数据结构、性能权衡 |
| AI Agent 系统 | 控制循环、上下文、工具、持久化、安全边界 |
| 小型工具 | 问题、核心算法、输入输出、限制 |

如果源码呈现的结构与仓库类别不一致，以实际调用链为准。

## 叙事方案的输出格式

研究完成后提出 2—3 种真实可行的方案。每种方案只需要说明：

1. 主线和读者首先建立的心智模型；
2. 章节之间的因果或时间关系；
3. 最适合解释的源码证据；
4. 优点、认知风险和可能遗漏；
5. 是否符合已经确认的 Diátaxis 类型。

给出明确推荐，不要为了凑数量提供明显较差的方案。

## 结构检查

- 全景图应出现在读者需要理解多个组件关系时，而不是固定放在开头。
- 生命周期适合解释生成、读取、反馈、治理和销毁，但不要为了对称虚构不存在的阶段。
- 每章解决一个主要认知问题；子问题必须共同服务于它。
- 配置、并发、成本、安全等内容放在改变主路径行为的位置，不单独堆成杂项章节。
- 结尾应完成观点收束或边界判断，不重复复述全部章节。
